PollyWAN setup and recovery

PollyWAN is disabled after installation. It does not publish local WAN defaults, change ports, scan USB, or alter GPS until an administrator enables it.

Android USB Tether

Android phone -> data-capable USB cable -> hAP USB host -> RNDIS/CDC/NCM -> wan3 DHCP

Connect a data-capable USB cable, unlock the Android phone, open hotspot/tethering settings, enable USB tethering, enable WAN 3 in PollyWAN, wait for DHCP, then verify health before selecting WAN 3. USB charging alone is insufficient.

The phone supplies DHCP, gateway, DNS, and NAT Internet access. Supported phones normally expose RNDIS, CDC Ethernet, or CDC NCM, but driver availability depends on the AREDN kernel and hardware. PollyWAN reports runtime USB-network support and leaves WAN 1/WAN 2 usable if WAN 3 USB support is unavailable.

GPS safety: when WAN 3 is disabled, PollyWAN never opens /dev/ttyACM0 or /dev/ttyUSB0, edits gpsd, changes AREDN GPS time/location, changes radio mode, or changes USB power. It searches only /sys/class/net after WAN 3 is explicitly enabled.
Health safety: gateway reachability is diagnostic only. A local gateway that answers ping does not prove Internet reachability; PollyWAN requires a source-bound external HTTPS health check before a path is upstream reachable.
Mesh export damping: table 28 is withdrawn on the first failed external upstream probe. Local failover keeps its own hysteresis, and recovered exits are not re-advertised until the export recovery count and hold-down pass.

Health and Selection

A reachable gateway does not prove that the Internet is reachable. PollyWAN validates the private table, records source-bound gateway reachability as a diagnostic, and then requires a source-bound external HTTPS response before treating a candidate as upstream-reachable.

A failed external probe removes the mesh-exported default immediately, while local selection may temporarily remain during its configured failure hysteresis. A recovered connection must pass multiple observations and the export hold-down before PollyWAN publishes it to the mesh again.

The optional secondary probe is attempted only after the primary probe fails. The endpoint is tested through the candidate source address with curl --interface "$SOURCE" --proxy '' and is not satisfied through another WAN. Cloudflare speed tests use the same direct source-bound path. Node-to-node iperf3 tests are unchanged.

Recovery

Use the PollyWAN disable action or remove the package to restore ordinary AREDN WAN behavior. Route rollback restores main, table 26, table 27, and table 28 snapshots after failed selection.

hAP Ports & XLinks

When PollyWAN Ethernet port-role control is enabled, the hAP Ports & XLinks page replaces AREDN's normal advanced port configuration page for that device.

XLinks remain normal AREDN XLinks. They are stored in the normal xlink UCI configuration and are not Internet WAN candidates.

Saving Ethernet roles must not remove XLinks. Saving XLinks must not change PollyWAN WAN-role VLAN assignments.
