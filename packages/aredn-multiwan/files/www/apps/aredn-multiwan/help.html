AREDN Multi-WAN and USB WAN

This is an experimental, optional package for the MikroTik hAP ac lite, hAP ac2, and hAP ac3. Installing it does not enable multi-WAN. The existing AREDN WAN remains unchanged until an administrator enables the package and selects another path.

Before installation: check free overlay space, especially on the hAP ac lite. The package installs USB network drivers, redsocks, curl, and nftables dependencies as separate APKs.

Interfaces

NamePurpose
wanExisting AREDN WAN.
wan2Second Ethernet WAN when it has been configured separately.
wan3USB RNDIS, CDC Ethernet, or CDC NCM tethering managed by this package.

PdaNet USB setup

  1. Use a data-capable USB cable and connect the Android phone to the hAP USB host port.
  2. Open PdaNet+ and enable Activate USB Mode. Leave PdaNet running.
  3. Log in to AREDN. Open the application menu and select aredn-multiwan.
  4. Open USB WAN, enable it, and leave the USB interface set to auto.
  5. Enable the upstream proxy when PdaNet requires it. Common defaults are 192.168.49.1, TCP port 8000, type HTTP CONNECT.
  6. Save. Wait for wan3 to show an IPv4 address, then select Use USB WAN now.
  7. Select Use WAN 1 before unplugging the phone when practical.

The package runs a private redsocks process with its own configuration, PID file, nftables table, and TCP listener on port 12346 by default. It does not stop or disable a separately configured stock redsocks service.

Proxy limitation: HTTP CONNECT carries TCP. General UDP, incoming connections, and port forwarding do not work through PdaNet proxy mode. UDP/443 is rejected so browsers normally fall back from QUIC/HTTP/3 to TCP/HTTPS. A standard routed Android tether can be used with the proxy disabled.

Link calibration

Only a logged-in administrator can start calibration. The browser cannot provide a test URL. The package uses the configured Hurricane Electric / Hayward Internet Exchange HTTPS object and requests bounded byte ranges:

  • 1 MiB initial sample
  • 8 MiB when the path is near or above 5 Mbps
  • 32 MiB when the path is near or above 30 Mbps

Maximum transfer is about 41 MiB. Results are low at 5 Mbps or less, medium above 5 through 30 Mbps, and fast above 30 Mbps. Calibration is measurement only in this package version; it does not yet perform automatic speed-based failover.

Verify from an authenticated shell

apk info -e aredn-multiwan
uci -c /etc/config.mesh show aredn.multiwan
/usr/local/bin/wan3-manager status
ubus call network.interface.wan3 status
ip -4 route show table main default
ip -4 route show table 103
cat /var/run/wan3-redsocks.pid
nft list table inet aredn_wan3_proxy
logread -e wan3-manager
logread -e redsocks
Healthy USB proxy state: wan3 is up with an IPv4 address, table 103 has a default route, the main table points through the USB device when selected, a private redsocks PID exists, and the aredn_wan3_proxy nftables table is present.

Recovery and uninstall

/usr/local/bin/wan3-manager select wan
/etc/init.d/wan3-manager stop
apk del aredn-multiwan

The package attempts to return to WAN 1 before removal. Saved aredn.multiwan settings are intentionally retained for a later reinstall. Existing sessions may not survive any WAN change.

Known unfinished work

  • The package can select and calibrate wan2, but does not yet create its physical hAP port/VLAN definition.
  • Automatic SLA and speed-bin failover are not enabled yet.
  • Calibration stays disabled until the exact Hayward HTTPS hostname and range-capable object are configured.
