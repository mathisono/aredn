AREDN Multi-WAN and phone USB tether

This is an experimental, optional package for the MikroTik hAP ac lite, hAP ac2, and hAP ac3. Installing it does not enable multi-WAN. The existing AREDN WAN remains unchanged until an administrator enables the package and selects another path.

Before installation: check free overlay space, especially on the hAP ac lite. The package installs USB network drivers, redsocks, curl, and nftables dependencies as separate APKs.

Interfaces

NamePurpose
wanExisting AREDN WAN.
wan2Second Ethernet WAN when it has been configured separately.
wan3Android phone connected to the hAP USB host as an RNDIS, CDC Ethernet, or CDC NCM tether.

Required USB topology

Android phone running PdaNet
        |
        | data-capable USB cable
        v
hAP USB host -> RNDIS/CDC network device -> wan3 DHCP
        |
        +-- optional PdaNet HTTP CONNECT proxy settings stored on the hAP

The hAP must first see a USB network adapter and obtain an IPv4 address on wan3. The PdaNet proxy is reached over that same USB network. A proxy address by itself is not enough when no USB network device or DHCP path exists.

PdaNet USB setup

  1. Use a data-capable USB cable and connect the Android phone directly to the hAP USB host port.
  2. Open PdaNet+ and enable Activate USB Mode. Leave PdaNet running.
  3. Log in to AREDN. Open the application menu and select aredn-multiwan.
  4. Open Phone USB Tether, enable WAN 3, and leave the hAP USB interface set to auto.
  5. Enable Use PdaNet upstream proxy when required. Enter the proxy information on the hAP. Common values are 192.168.49.1, TCP port 8000, type HTTP CONNECT.
  6. Optional username and password fields are also stored and used by the hAP.
  7. Save. Wait for wan3 to show an IPv4 address, then select Use phone USB tether now.
  8. Select Use WAN 1 before unplugging the phone when practical.

The package runs a private redsocks process with its own configuration, PID file, nftables table, and TCP listener on port 12346 by default. It does not stop or disable a separately configured stock redsocks service.

Proxy limitation: HTTP CONNECT carries TCP. General UDP, incoming connections, and port forwarding do not work through PdaNet proxy mode. UDP/443 is rejected so browsers normally fall back from QUIC/HTTP/3 to TCP/HTTPS. A standard routed Android USB tether can be used with the proxy disabled.

User-selected link calibration object

A logged-in administrator sets a descriptive label and a complete HTTPS object URL in WAN Link Calibration. The object is not hard-coded. Hurricane Electric/Hayward may be used, but any suitable administrator-selected HTTPS object is allowed.

The object must use a valid certificate, include a DNS hostname and path, support byte ranges, return HTTP 206, contain at least 32 MiB, and avoid redirects. Embedded credentials, spaces, fragments, and custom ports are rejected. Saving a blank URL disables calibration.

A calibration run can select only wan, wan2, or wan3; the run request cannot supply or replace the saved URL.

  • 1 MiB initial sample
  • 8 MiB when the path is near or above 5 Mbps
  • 32 MiB when the path is near or above 30 Mbps

Maximum transfer is about 41 MiB. Results are low at 5 Mbps or less, medium above 5 through 30 Mbps, and fast above 30 Mbps. For wan3, calibration remains bound to the phone USB tether and directly uses the saved PdaNet proxy when enabled.

Verify from an authenticated shell

apk info -e aredn-multiwan
uci -c /etc/config.mesh show aredn.multiwan
/usr/local/bin/wan3-manager status
ubus call network.interface.wan3 status
ip -4 route show table main default
ip -4 route show table 103
cat /var/run/wan3-redsocks.pid
nft list table inet aredn_wan3_proxy
logread -e wan3-manager
logread -e redsocks
logread -e wan-calibrate
Healthy USB proxy state: wan3 is up with an IPv4 address, table 103 has a default route, the main table points through the USB device when selected, a private redsocks PID exists, and the aredn_wan3_proxy nftables table is present.

Recovery and uninstall

/usr/local/bin/wan3-manager select wan
/etc/init.d/wan3-manager stop
apk del aredn-multiwan

The package attempts to return to WAN 1 before removal. Saved aredn.multiwan settings are intentionally retained for a later reinstall. Existing sessions may not survive any WAN change.

Known unfinished work

  • The package can select and calibrate wan2, but does not yet create its physical hAP port/VLAN definition.
  • Automatic SLA and speed-bin failover are not enabled yet.
  • The package build and physical installation tests are the next development step.
